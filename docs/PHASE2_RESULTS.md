# Phase 2 구현·검증 결과

검증일: 2026-10-21. 범위는 `PROJECT_SPEC.md`의 Phase 2다. **챗봇을 주 화면**으로 만들었고 Phase 3·4의 팀·전투 계산은 시작하지 않았다.

## 구현

- React·TypeScript·Vite·Tailwind 화면과 FastAPI를 연결했다. 대화 영역이 중심이며 포켓몬 탐색은 왼쪽 보조 패널이다. 종족값·원문은 펼쳐서 확인하고 모바일 검색은 기본적으로 접힌다. 공식 이미지·스프라이트는 추가하지 않았다.
- 포켓몬별 대화 목록·새 대화·기록 선택·메시지 복원을 제공한다. 브라우저 새로고침 후 같은 익명 세션의 기록을 복원한다. 다른 세션의 기록은 접근할 수 없다. 전송 후 포켓몬을 바꿔도 응답은 원래 포켓몬의 작업에 연결된다.
- `근거 운용 가이드`도 같은 수집→검색→생성→인용 검증을 사용하고 대화에 저장한다. 일반 도감의 특징·문서에서 확인되는 특성 설명을 제공하며, 근거 없는 역할·Champions 적용 여부는 미확인으로 분리한다.
- 자연어 조건을 모델로 구조화하고 메타 컬렉션 전체를 검색한 뒤 실제 도감 필드로 AND 조건을 검증한다. 정확 일치 집합을 의미 검색 순위로 정렬한다. 불명확한 기준·OR·미지원 전투 조건은 구체화를 요청한다. 해석된 조건을 화면에 보여 주며 유사도를 확률로 표시하지 않는다.
- 수집·검색·생성 상태를 작업 조회로 표시한다. 실패 후 재시도, 키/색인 누락, 빈 결과, 근거 부족, 연결 오류를 구분한다. 질문·답변을 HTML로 실행하지 않고 실제 인용한 HTTPS 원문만 링크한다.

주요 변경: `frontend/`, `backend/discovery.py`, 대화·가이드 API와 SQLite 조회, 구조화 검색 모델, 가이드 저장, 인용 버전 정규화 및 테스트. README·API/아키텍처 문서·OpenAPI를 갱신했다.

화면 캡처는 대화가 포함될 수 있어 `runtime-ui/`에 로컬 전용으로 보관하고 Git에서 제외했다. 배포 빌드·node_modules·브라우저 결과 디렉터리도 제외했다. PDF·`.env`·기존 개인 학습 문서의 제외 규칙을 유지했다. 이번 단계에서 커밋·푸시는 하지 않았다.

## 발견한 문제와 수정

1. 첫 실제 조건 검색은 명확한 일반 도감 조건에도 확인 요청을 반환했다. 일반 도감 범위와 구체적인 구조화 예시를 명시하고 검색·생성의 온도를 0으로 설정했다. 최종 실행에서 원본 3종과 일치했다. LLM 해석 자체의 정확성을 보증하는 것은 아니다.
2. 실제 가이드에서 버전 배열이 빈 배열 대신 `[""]`로 생성되어 인용 검증이 두 차례 실패하고 안전하게 유보됐다. 공백 버전 표시는 ‘버전 없음’으로 정규화했다. 비어 있지 않은 버전은 여전히 인용 본문과 대조하며, 가짜 버전은 회귀 테스트에서 거부한다. 검증 실패를 성공 인용으로 숨기지 않는다.
3. 가이드에 확인된 정보와 미확인이 함께 있어도 모델이 answered를 반환하는 경우가 있었다. 실제 주장과 미확인이 공존하면 서버가 partial로 표시한다. 가이드 요청의 내부 템플릿 대신 짧은 사용자 요청을 기록한다.

## 남은 한계와 체크리스트

- [x] 자체 구현 점검, 자동 테스트, 실제 모델 및 브라우저 연결, 출처·민감정보 제외 검사.
- [ ] 외부 동료의 상호 점검: 실행하지 않았으므로 완료로 표시하지 않는다.
- [ ] 과제 담당자의 React 제출 경로 수용 확인: PDF 준비 기술의 Streamlit과 F2013 별도 UI 허용의 해석 문제는 미해결이다. 사용자 프로젝트 명세대로 React를 구현했고 Streamlit 대체 화면은 추가하지 않았다.
- [ ] Champions의 현재 규칙·적격성·전략 근거 확보: 일반 도감의 100종을 참가 가능 100종으로 표시하지 않는다. 역할·추천 세트·승률·데미지를 생성한 것으로 간주하지 않는다.

현재 실사용 목록은 도감·조건 결과 첫 100종, 대화 목록 최신 100개까지다. 메시지는 전체 페이지를 읽는다. 데이터 확장 시 목록 페이지 UI가 필요하다. 한국어 의미 검색은 영어 중심 임베딩의 한계가 있고, 조건 전체가 정확히 구조화됐는지는 화면의 해석과 대조해야 한다. 인용 ID·버전 유효성은 생성 문장 전체의 사실 정확성을 증명하지 않는다. 특히 특성의 주체·대상·조건 같은 의미 오류는 원문 확인이 필요하다.

개인용 로컬 단일 프로세스 운영을 기준으로 한다. 세션 만료·쿠키 삭제 후 기록 접근, 장기 데이터 삭제 정책, 계정 인증·다중 사용자 운영은 별도 과제다. 첫 로컬 테스트에서 포트/브라우저 실행은 샌드박스 권한으로 제한돼 승인된 실행으로 재검증했다. 외부 공개 배포와 성능 보장은 검증하지 않았다.

다음 명세 단계는 Phase 3 팀·전투 보조이나, 사용자 요청 전에는 착수하지 않는다.
