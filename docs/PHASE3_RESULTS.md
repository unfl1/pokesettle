# Phase 3 팀·전투 보조 구현 결과

> 이 문서의 SQLite 상태 저장은 해당 단계 실행 당시 기록임. RAG의 ChromaDB 사용은 유지하며, 현재 상태 저장과 검증은 [PostgreSQL 전환 기록](POSTGRESQL_MIGRATION.md) 참조.

검증일: 2026-10-21. 작업 브랜치: `develop`. 범위: 일반 도감·타입표 기반 팀 준비와 전투 시나리오 비교. 챗봇 기본 화면 유지. Champions 현행 레귤레이션의 합법 판정과 정밀 전투 계산은 미지원임.

## 구현

| 영역 | 변경 내용 |
|---|---|
| 팀 편집·저장 | 내 팀·상대 팀 각각 최대 6마리, 전체 도감 이름 검색·페이지 이동·이미지·타입 표시, 기술 4개·HP·특성·도구 입력 |
| 저장 경계 | 기존 익명 세션에 연결한 SQLite 팀 생성·목록·조회·수정·삭제, 재접속 시 같은 세션으로 복원, 타 세션 접근 404 처리 |
| 입력 검증 | 같은 종의 다른 폼을 포함한 중복 방지, 슬롯·HP·타입·기술 수·미등록 포켓몬 검증. 중복 제한은 팀 편집 정책이며 현행 규칙 판정과 구분 |
| 타입 분석 | 일반 타입표 18×18 관계와 이중 타입 배율 곱, 공격 커버리지·공통 약점·반감/무효 대응 표시 |
| 선출 비교 | 양쪽 6마리 입력 시 내 팀의 3마리 조합 20개 열거, 점수 구성·선봉 비교 후보 표시, 합법 후보·승률로 표시하지 않음 |
| 전투 비교 | 입력 기술별 타입 배율, 상대 입력/가정 공격에 대한 교체 후보의 최악 배율, 쓰러진 멤버·교체 봉쇄 제외 |
| 메가 상태 | 미확인·미사용·사용 완료 구분, 같은 종의 도감 메가 폼 전후 방어 타입 비교. 사용 완료·이미 메가 폼·쓰러진 상태의 추가 전환 비교 제외 |
| 챗봇 연결 | 팀 구성으로 질문 초안 준비, 사용자 전송 전 모델 호출 없음, 챗봇 왕복 시 편집 상태 유지 |
| 상태·근거 | 입력 변경 시 이전 분석 결과 숨김, 진행·안전 오류·재시도, 계산 범위·가정·미확인·출처 링크 표시 |

공격 비교는 높은 타입 배율 순, 교체 비교는 낮은 최악 배율 순으로 각각 표시함. 공격과 교체의 전역 최적 행동은 반환하지 않으며 `recommendedAction=null` 유지. 변화 기술의 타입 배율은 `null`로 표시함.

## 점수와 가정

- 선출 점수: `약점 공략 상대 수 × 2 + 가정 공격 반감·무효 대응 수 − 중복 약점 수`.
- 반감 대응: 상대별 입력/가정 공격 타입 모두에 1배 미만으로 대응 가능한 멤버의 존재 여부 기준.
- 중복 약점: 공격 타입별 약점 멤버 수에서 첫 멤버를 제외한 수의 합.
- 기술 미입력 시 해당 포켓몬 타입의 공격 보유 가정. 변화 기술만 입력한 경우 공격 커버리지 판정 유보.
- 선봉 비교 후보: 같은 척도의 단일 멤버 점수 기준. 행동 순서와 실제 역할 적합성 미검증.
- HP 미입력 멤버: 생존 가능 시나리오에 포함, 실제 생존·남은 HP 미확인.
- 점수는 확률이 아닌 프로젝트 자체 휴리스틱임. 동점은 입력 순서 유지.

## 검증

| 검증 | 결과 |
|---|---|
| 전체 백엔드 pytest | 43개 통과 |
| Ruff 검사·형식 | 통과 |
| TypeScript 검사·Vite 빌드 | 통과 |
| 모의 API Chrome E2E | 기존 13개 + 팀·선출·모바일 3개, 총 16개 통과 |
| 실제 로컬 API·UI | 도감 12개 멤버의 팀 분석, 선출 20개, 근거 14개 연결 확인 |
| 실제 메가 타입 비교 | 리자몽→메가리자몽 X의 전기 방어 2×→0.5× 확인. 일반 타입표 범위이며 전환 합법성·실제 피해 검증 아님 |
| 실제 모바일 화면 | 390×844, 기술 입력 펼침 상태의 가로 넘침 없음·브라우저 런타임 오류 없음 |
| 타입표 재수집 | 최초 외부 호출 1회·캐시 1회, 재실행 외부 호출 0회·캐시 2회 |

실제 로컬 연결 검증 요약은 [phase3.json](evidence/phase3.json)에 기록함. API 대역 테스트와 실제 SQLite·도감·계산 API 연결 검증을 구분함. 실제 연결 검증에서는 모델 호출 없음. 검증용 저장 팀은 종료 후 삭제함. 화면 캡처·실행 스크립트는 Git 제외 경로 `runtime-ui/`에 보관함.

## 파일과 구조

- `backend/battle/`: 요청 모델·일반 타입 분석·선출 휴리스틱·전투 대안 모듈 추가. RAG·모델 호출과 분리.
- `backend/storage.py`, `backend/main.py`: 세션 소유 팀 저장·조회 및 분석 API 추가. PUT·DELETE의 CORS·Origin 검사 적용.
- `backend/scripts/prepare_battle_data.py`, `data/type_chart.json`: 캐시를 이용한 CSV 수집·324개 관계 검증·출처/시각/해시/권리 기록.
- `frontend/src/components/TeamEditor.tsx`, `TeamWorkspace.tsx`, `services/battle.ts`: 보조 화면·입력·결과·API 계약 추가. 기존 화면과 같은 Tailwind 테마 사용.
- `backend/tests/test_battle.py`, `frontend/e2e/battle.spec.ts`: 계산 경계·세션 격리·팀 CRUD·선출·전투·모바일 회귀 테스트 추가.

## 요구사항 추적과 남은 범위

- F2001–F2012: 기존 기능 유지, 백엔드·브라우저 회귀 테스트 통과. 이번 단계에서 필수 요구사항을 새로 충족한 것으로 중복 집계하지 않음.
- Phase 3: 팀 저장·일반 상성·선출 휴리스틱·공격/교체 대안·메가 상태 비교 구현.
- 미확인: 현재 레귤레이션과 참가 명단, 폼·기술·도구 허용 여부, 메가 스톤·타이밍·횟수의 현행 세부 조건, 특성·필드·진입 피해·행동 순서·기술 효과.
- 역할 간극: 회복·설치·제거·속도 제어는 기술 효과 자료 부족으로 판정 유보. 단순 종족값으로 역할을 확정하지 않음.
- 챗봇 연결: 팀 이름·구성을 사용자 질문 초안으로 전달. 계산 결과를 RAG 도구 컨텍스트에 자동 주입하거나 자동 답변 생성하는 기능은 미구현.
- 세션 만료·쿠키 삭제 후 팀 접근과 계정 인증·복구 기능은 기존 익명 운영 범위 밖임.
- Phase 4의 데미지·조건부 KO·고급 시뮬레이션·MMR·추가 출처 색인은 미착수.

다음 작업 전제: 공식 현행 규칙 스냅샷과 재현 가능한 계산 사례 확보. 일반 타입 시나리오를 Champions에서 검증된 추천으로 승격하지 않음.
